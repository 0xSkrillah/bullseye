# Claim ledger

Every claim Bullseye makes about itself, what backs it, and what does not. If a claim is not in
the "Verified" table with evidence you can run or open, do not repeat it in a pitch, a README or
a demo. Last reviewed: 19 September 2026.

Status values: **VERIFIED** (evidence in this repo, reproducible) · **PARTIAL** (mechanism built
and tested, but not against the real external system) · **BLOCKED** (cannot be done yet; reason
given) · **NOT CLAIMED**.

Rows V18 to V21 were P1, P2, P3 and B2 until the first live run on 18 September 2026. Each is
scoped to what was observed that day: one investigation and one testnet settlement.

Rows V34 to V41 were added on 19 September 2026, after an outside review of commit `1ae8e79`
found that the browser could not complete or recover a purchase, that the read routes gave away
buyers' orders and most of what a Brief sells, and that the gate's number rule could be passed
by figures with no evidence behind them. Each of those rows is verified by tests that run
offline: recorded data, the fixture synthesiser, the fixture payment rail and a stand-in wallet.
None of them has been exercised with a wallet extension, on a real rail, or on the deployed
service. B5 is the list of what that would take.

| V36 | Gate 2.0.0 binds every figure in a draft to typed evidence. A unit registry owned by code gives each numeric evidence key a unit class. In a claim, each figure written in digits must bind to one of that claim's declared quantities: the unit as written must fit ("%" only for percentages, "$"/"USD" only for USD, a fraction only in its typed percentage form), the sign must match (a direction word may carry it on signed fields only), and the figure must be the value correctly rounded with at least two significant digits. A spelled-out figure with a unit is refused. While a core check is not PASS, a headline or rationale that announces a confirmation fails `FAILED_CHECKS_DISCLOSED` even when the conflict is listed.
