# Mapping to the React / Vite implementation

The repo is an npm workspace: `packages/domain` (Zod schemas — the source of truth for every enum in this system), `apps/api` (Express) and `apps/web` (React/Vite, to be built). The system ships as CSS custom properties plus a small class contract (`components/bundle.css`) and a vanilla helper bundle (`components/bundle.js`, global `Bullseye`) that the previews use. The web app consumes the tokens and the class contract; it renders `@bullseye/domain` types directly and does not import the helper bundle.

## Domain → component mapping

| Domain type | Component | Notes |
| --- | --- | --- |
| `SignalEvent` | SignalCard | `provenance.mode` → badge; `facts` → facts strip; `sources[]` → drawer on click |
| `DataMode`, `Provenance` | ProvenanceBadge | STALE is derived: `now > staleAfter`; TESTNET is derived from `PaymentRail` |
| `EvidenceItem` | EvidenceDrawer | `values` rendered as a key/value table; `summary` is code-written, show verbatim |
| `InvestigationView.timeline[]`, `UsageRecord[]`, `ResearchBudget`, `StopReason` | InvestigationTimeline | glyph from `type` × `ok`; footer sums `UsageRecord.costUsd` where basis ≠ FIXTURE |
| `BriefDraft.confidence`, `GateResult.confidenceCap` | ConfidenceIndicator | arcs = level; cap note when `cap` < `level` |
| `BriefDraft.unknowns`, `.conflicts`, `ConsistencyCheck[]` | UnknownsPanel | conflicts join `checks` by `checkId` for status |
| `Quote`, `QuoteTerms` | BriefPaywall | render `terms` once, freeze with `useMemo` on `termsHash`; never reformat after mount |
| `Order`, `OrderState`, `OrderEvent[]`, `PaymentEvidence` | PaymentState | ladder from `ORDER_TRANSITIONS`; `events[]` is the audit trail under the ladder |
| `EconomicsReceipt`, `CostLine`, `CostBasis` | EconomicsReceipt | `measuredCosts` and `estimatedCosts` are separate tables; never one total |
| `GateResult`, `GateFinding`, `GateRule` | PublicationGateResult | rows in `GateRule` enum order; failing rows first only in REJECT |

## `<Money>` — one primitive, one rule

```ts
type MoneyProps = { usd: number | string; basis: 'MEASURED' | 'ESTIMATED' | 'PRICE'; realised?: boolean; rail?: PaymentRail };
```

Renders `uncertain` colour, the `≈` glyph and the word "estimated" whenever `basis === 'ESTIMATED'`; renders `verified` only when `basis === 'PRICE'` and `realised` is true (order state PAID or later); appends the TESTNET tag and "Not revenue." when `rail` is `OKX_X402_TESTNET` or `FIXTURE`. There is no prop to override the colour. Every amount on every screen goes through this component so the brand rule cannot be bypassed.

## Class names

Prefix `be-`. Block-element without double dashes: `be-card`, `be-tl-row`, `be-badge be-badge-live`. State classes are `is-*` (`is-locked`, `is-stale`, `is-expired`); provenance and order classes are the enum value lowercased with underscores kept: `be-badge-cached`, `be-pay-payment_unknown`.

## Motion

Use the View Transitions API for Feed → Brief (`document.startViewTransition`) with `view-transition-name: signal-header` on the SignalCard header and the Brief title; fall back to a plain route change. Everything else is CSS transitions at the durations in the brand book, gated by `@media (prefers-reduced-motion: reduce)`.

## Demo mode and fixtures

Fixture data enters only through adapters that stamp `mode: 'FIXTURE'`; the UI never sets a mode. `weakestMode()` from the domain decides the Brief header badge. The radar hero seeds its noise from `artifacts/recorded/` when present and locks on the first `SignalEvent` the API returns.

## Tests that protect the brand (Vitest + Playwright)

1. `<Money basis="ESTIMATED">` never renders with the `verified` colour and always contains the word "estimated".
2. Every `ProvenanceBadge` renders its word, not only its dot.
3. `PaymentState` in PAYMENT_UNKNOWN renders "A retry cannot charge you twice." verbatim and offers no "Pay again" button.
4. `EconomicsReceipt` never renders a row whose label contains "Total" spanning measured and estimated lines.
5. The Brief screen always renders all eight section headings and the disclaimer string from `DISCLAIMER`.
